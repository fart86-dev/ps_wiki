## 이슈 목록

### 1. dispatch_cd 모델 정의 — 해결됨

**문제:** operation.md와 dispatch_cd.md 상태그래프가 충돌
- operation.md: "a, b는 별개 레코드"
- dispatch_cd.md: "a ↔ b 상태 전이"

**결론:** a=일반운행배차, b=대차운행배차. **별개 레코드**가 맞음. 상태 전이가 아님.
→ dispatch_cd.md 상태그래프 수정 필요

---

### 2. apply_cd 역방향 전이 — 해결됨

**문제:** 유료(a) → 무료체험(c) 전환이 불가능한가?

**결론:** 한 row 내에서는 불가능. 현재 탑승(c)이 종료된 후 새로운 연장(a) 신청을 하는 구조.
→ 문서에 "row 단위 라이프사이클"임을 명시하면 혼동 방지

---

### 3. board → runn_cald 매핑 — 해결됨

**문제:** 탑승확정 유저가 어떤 운행일정에 연결되는지 미정의.

**결론:** `board.rt_id` + 오늘 날짜(`YYYY-MM-DD`)로 `runn_cald` 조회.
→ runn_cald는 "경로가 오늘 운행하는지"에 대한 테이블이지, 유저 단위가 아님

---

### 4. board_cd 상태 rt_cd별 차이 — 해결됨

**문제:** boarding.md에 rt_cd별 차이 명시 부족.

**결론:** 문서에 존재함. `wh`(when) 조건에서 확인 가능.
→ 이슈 아님

---

### 5. 환불 시 board_cd 전이 — 해결됨

**문제:** 환불 시 board_cd가 자동 변경되는지?

**결론:** board_cd는 변하지 않음. 환불 방식에 따라 사람이 결정.
→ 시스템 자동 전이 아님

---

### 6. 경로 활성화 조건 (min_user_cnt) — 해결됨

**문제:** min_user_cnt 정의가 모호.

**결론:** rt_cd='c'(예정) 상태에서 해당 숫자만큼 인원이 모이면 배차를 구하고 운행을 시작하겠다는 기준값.
→ 문서에 이 설명 보강 필요

---

### 7. dr_setl 차감 공식 — 해결됨

**문제:** 두 곳에서 다르게 기술됨.

**위치 1** (상세 산출식):
```
공급가액 = 월계약운행비 + 이슈추가비 - 이슈제외비 + 미운행금액
```

**위치 2** (차감 케이스별 산출):
```
당일 미운행 = 월기사비 / 월영업일수 × 미운행일수
```

**결론:** 당일 미운행은 **미운행금액**에 포함됨. 이슈제외비와는 별개.
- 미운행금액 = 미운행일에 대한 일할 차감 (당일 미운행 포함)
- 이슈제외비 = 이슈 기반 차감 (별도)
→ 문서에 이 관계를 명시하면 혼동 방지

### 10. runn_cd 테이블 위치 — 해결됨

**문제:** runn_cd가 어떤 테이블의 값인지.

**결과:** 2개 테이블에 존재하며 **의미가 다름**

| 테이블 | 칼럼명 | 값 | 의미 |
|--------|--------|-----|------|
| `cald` | `runn_cd` | 0=영업일, 1=비영업일 | 전역 캘린더 (날짜가 영업일인지) |
| `runn_cald` | `runn_cd` | a=운행, b=미운행 | 경로별 운행일정 (그 경로가 그날 운행하는지) |

→ 같은 칼럼명이지만 타입(INT vs VARCHAR)도 다르고 의미도 다름. 혼동 주의.

### 13. board_cd='e' 전이 경로 — 해결됨

**문제:** 대기(e) 상태에서의 전이가 불완전.

**결론:** 좌석이 없을 때 e로 처리. 자리가 비면 사람이 수동으로 a(탑승신청)로 변경.
→ 시스템 자동이 아닌 수동 전이
