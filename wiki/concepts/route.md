# 경로 (Route)

mshuttle의 모든 운행을 시작하는 핵심 단위.

## 경로 생성의 두 가지 경로

### 1. 요청 기반 (기업/단체 - 견적 요청)
외부 업체/개인이 홈페이지나 전화로 셔틀 운행을 요청:
- **가견적 생성** → 경로 및 기사 조건 검토
- **견적 확정** → 업체와 조율 후 계약
- **경로 생성** → 정식 경로 등록
- **특징**: 탑승 인원 이미 확보 → 배차로 직진

→ [견적 프로세스](../concepts/quotation.md)

### 2. 수요 기반 (알림받기 신청)
유저가 홈페이지 알림받기로 신청:
- 운영팀이 신청 데이터 분석 (집 위치, 회사, 시간)
- **경로 생성 가능한 그룹 판단**
- **경로 생성**
- **마케팅** (전화/문자로 목표 인원 모집)
- **배차로 진행**
- **특징**: 정기 경로만 생성, 마케팅 단계 있음

## 경로 유형

| 유형 | 특징 | 배차 전 준비 |
|------|------|-----------|
| **기업/단체 정기 (기본)** | 탑승자 확정 | 직접 배차 |
| **기업/단체 정기 (부가서비스)** | 관제 등 필요 | 유저 가입·연동 후 배차 |
| **기업/단체 비정기** | 1회성 운행 | 직접 배차 |
| **일반 경로** | 유저 모집 | 일정 인원 충족 후 배차 |

## 경로 상태

### 운행예정
- 유저 탑승 신청 수락
- 일정 인원 모음
- 배차 완료 시 "운행" 상태로 전환

### 운행
실제 운행 단계:
- [기사 운행](../concepts/driver-operation.md) / [관제](../concepts/control.md) / 탑승 동시 진행
- 기사 교체 시 배차 재발생
- 인원 감소 시 [충원/통폐합/폐지](../concepts/route-management.md) 검토

### 일시중단
특정 기간 중단 (상태값 변경 아님, 기간 데이터 추가):
- 기간 종료 시 자동 재개
- 기사비 정산에서 해당 일자 차감

## 일반 경로 상품화

- **2일 무료 체험** 후 1달 상품 전환
- **1달 단위** 상품 운영
- 탑승 종료 4일 전 신규 데이터 자동 생성 + 결제 요청 문자

## 인원 감소 시 처리 순서

1. **인원 충원** (마케팅)
2. **경로 통폐합** (유사 경로 병합)
3. **경로 폐지** (위 두 방법 모두 불가)

## 수요 기반 경로의 핵심: 클러스터

수요 기반 경로 생성 시 [클러스터 (Clustering)](../concepts/clustering.md)가 기초가 됩니다:
- 지도를 육각형 구역으로 자동 분할
- 같은 구역의 신청자들을 그룹화
- Zoom으로 구역 크기 조절
- **클러스터 토글을 켠 상태에서 경로 가능한 그룹 판단**
