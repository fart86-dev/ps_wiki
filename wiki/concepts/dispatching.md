# 배차 (Dispatching)

경로에 기사를 배정하는 프로세스. 같은 배차이지만 발생 시점과 목적이 다름.

## 두 가지 배차 상황

### 1. 운행예정 상태의 배차
**목적**: 운행을 시작하기 위한 초기 배차

- 일정 인원이 모임 → 운영팀이 기사 배정
- 배차 완료 후 [시뮬레이션](../concepts/simulation.md) 진행 (정기만)
- 완료 후 경로가 "운행" 상태로 전환

### 2. 운행 상태의 배차
**목적**: 운행을 유지하기 위한 기사 교체 배차

- 운행 중 기사가 그만둘 경우 배차 재발생
- 배차 완료 후 "운행" 상태 유지 (상태 전환 없음)

## 배차 프로세스 (상세)

### 1단계: 기사풀 확인
- 배차 가능한 기사 목록 확인

### 2단계: 기사 선택
- **기사 확보 가능?**
  - Yes: 운영팀이 직접 선택 (연계 운행 시간 확인)
  - No: 기존 기사에게 연락 → 다른 기사 추천받음

### 3단계: 의사결정
- 운영팀이 **연계 운행 시간 확인** (시스템)
- 기사의 수익성, 효율성 판단
- 기사에게 제안

### 4단계: 기사 응답
- **수락?**
  - Yes: 배차 확정으로 진행
  - No: 다른 기사 탐색 (2단계로 돌아감)

### 5단계: 배차 확정
- 기사 확정
- 시뮬레이션 (정기만) → [시뮬레이션](../concepts/simulation.md)

### 6단계: 승객 안내
- 승객에게 탑승 안내 (전화/문자)
- 경로 최종 수정 (승객의 실제 위치·시간 요청 반영)

### 7단계: 운행 시작
- 운행 상태 진입

## 배차 가능 시점

| 상태 | 트리거 | 비고 |
|------|--------|------|
| 운행예정 | 일정 인원 충족 | 초기 배차 |
| 운행예정 | 기업 정기 계약 성사 | 부가서비스 연동 완료 후 |
| 운행예정 | 기업 비정기 계약 | 직접 배차 |
| 운행 | 기사 퇴사/교체 | 기사 교체 배차 |
