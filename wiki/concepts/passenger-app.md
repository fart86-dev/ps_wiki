# 탑승자 앱 (Passenger App)

탑승자(유저)가 셔틀을 예약·탑승하는 데 사용하는 모바일 앱. 리포지토리는 `rtn_psn`(모두의셔틀 탑승자).

> mshuttle 서비스 흐름에서 **탑승(유저 탑승)** 노드를 담당하는 클라이언트. [기사 운행](./driver-operation.md)의 유저 측 대응.

## 특징

- **하이브리드 WebView 셸**: 화면·비즈니스 로직은 원격 웹(`psnapp.mosher.co.kr`)에 있고, 앱은 네이티브 능력만 브릿지로 제공.
- **네이티브 능력 노출**: GPS/위치, 권한, 푸시 알림, 배터리·절전·방해금지, 화면 방향, 채널톡 상담 등.
- **자체 OTA**로 웹 자산이 아닌 JS 번들을 무선 갱신 (앱 시작 시 선행).

## 서비스 흐름 내 위치

```
견적/수요 → 경로 생성 → 배차 → 운행 상태
                                   ├─ 기사 운행 (기사 앱)
                                   ├─ 관제 (운영팀)
                                   └─ 탑승 (유저) ← 탑승자 앱(rtn_psn)
```

## 위치(GPS) 처리

- 탑승자 GPS는 네이티브에서 수집해 **웹으로 전달**하는 구조(리스너/브릿지)로 보이나, 앱이 배차/실시간 위치 서버로 직접 올리는지는 미확정.
- > 확인 필요: 탑승자 위치가 [관제](./control.md)/[배차](./dispatching.md)의 실시간 데이터에 직접 관여하는지, 아니면 웹 경유인지.

## 중요 주의점

> **앱은 도메인 로직의 정본이 아니다.** 예약·탑승 규칙은 웹(psnapp)에 있으므로, 탑승 도메인 규칙을 앱 코드에서 유추하면 안 된다.

- 기사 측 [기사 운행](./driver-operation.md)과 달리, 탑승 체크의 정본은 기사 앱이 담당(기사가 직접 체크). 탑승자 앱은 유저 경험·상담·위치 제공 중심.

## 레포 간 관계

- 드라이버 앱(rtn_drapp)과 브릿지/OTA/리스너 계약을 **정렬(sync)** 중 — 공통 기술 계약 추출 가능성. (needs-verification)
