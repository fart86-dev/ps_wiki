# 경로 제작 및 배차

**원본:** raw/papers/route_and_dispatch.md

## 핵심 발견

경로 제작과 배차는 운행이 시작되기까지의 두 단계로, 각 단계에서의 의사결정이 운영 효율성을 결정합니다.

## 경로 생성의 두 경로

### 1. 수요 기반 (홈페이지 알림받기)

```
알림받기 신청 접수
    ↓
운영팀이 신청 데이터 분석 (집 위치, 회사, 시간)
    ↓
경로 생성 가능한 그룹 판단
    ↓
경로 생성
    ↓
마케팅 (전화, 문자) → 목표 인원 달성
    ↓
배차
```

특징: 마케팅 단계 있음

### 2. 요청 기반 (기업/단체)

```
기업/단체 요청 접수 (인원, 출발지, 목적지, 시간)
    ↓
경로 생성
    ↓
배차
```

특징: 탑승 인원 이미 확보 → 마케팅 단계 없음

## 배차 프로세스

```
기사풀 확인
    ↓
기사 확보 가능?
├─ Yes: 운영팀이 기사 선택 (연계 운행 시간 확인)
└─ No: 기존 기사에게 연락 → 다른 기사 추천받음
    ↓
기사에게 제안
    ↓
수락? 
├─ Yes: 배차 확정
└─ No: 다른 기사 탐색 → 반복
    ↓
승객 탑승 안내 (전화/문자)
    ↓
경로 최종 수정 (승객 위치·시간 요청 반영)
    ↓
운행 시작
```

## 배차 의사결정의 핵심

### 연계 운행 (Chaining)
- **목표**: 기사 한 명이 하루에 여러 경로를 연속 운행
- **최적화**: 경로 간 시간과 위치 맞춰 공차(deadheading) 최소화
- **도구**: 시스템에서 기사별 운행 시간 확인 가능 → 배차 전 반드시 확인
- **영향**: 공차 감소 = 운영 효율 증대

### 경로 최종 수정
- **시점**: 배차 확정 후, 운행 시작 전까지
- **내용**: 승객의 실제 위치, 시간 요청 반영
- **유연성**: 초기 경로는 추정, 최종 확정은 실제 수요 기반

## 경로 생성의 기술적 기초: 클러스터

- **클러스터**: 지도를 육각형 구역으로 자동 분할
- **Zoom**: 육각형 크기 조절 (숫자 크면 좁아짐, 작으면 넓어짐)
- **의사결정**: 클러스터 토글을 켠 상태에서 경로 가능한 그룹 판단

경로 생성 불가능한 경우: 클러스터 미이해 → 경로 그룹 판단 실패

## 시스템 프로세스

경로제작 화면에서 6단계로 진행:
1. 탑승자 데이터 불러오기 (필터: 기간, 시간, 지역)
2. Point 찍기 (정류장 후보)
3. LineString 생성 (Tmap 길찾기)
4. 정류장 확정
5. 경로 생성 (자동: 정류장 생성 + 탑승자 할당)
6. 경로 제작 (수동: 메타데이터 입력 + 저장)

## 경로 메타데이터 (10개 항목)

| 항목 | 설명 | 오류 시 영향 |
|------|------|-----------|
| 탑승지/하차지 | 정류장 주소 | 고객이 경로를 찾지 못함 |
| 시간 | 운행 시간 | 잘못된 시간에 운행 |
| 결제 | 요금 청구 여부 | 결제 실패 |
| 활성 | 현재 운영 여부 | 앱에 미표시 |
| 출퇴근 | 방향 구분 | 반대 방향 운행 |
| 사업 | B2C vs B2B | 정산 오류 |
| 좌석 | 선택 vs 자동 배정 | UX 혼란 |
| 검색 | 앱 노출 여부 | 고객이 경로를 찾지 못함 |
| 경로추천 | 추천 시스템 등록 | 신규 경로 가시성 저하 |
